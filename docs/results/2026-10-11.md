## 2026-10-11 12:50 — The public server's data: a fuller daily pull (raw logs, seven days on the server, an index, a second copy)

The owner asked for the best routine for pulling the game data to the PC and wiping it from the server; to the six
points proposed: "yes to all, make it 7 days". The daily pull of 2026-10-07 stays (`tools/pull_sessions.sh`, 09:30);
what it lacked:

- **Raw logs were never pulled.** `server.log` and `duelbot.log` stayed on the server for good, the first with
  visitors' Steam IDs and addresses; `minqlx.log`, the only one with a time on every event, lived in the container and
  went with every rebuild (the count of who had played overnight on 2026-10-10 had a hole of six hours for it). Now
  `minqlx.log` is written to the data folder (`QLX_LOG_DIR`, the day in its time stamps), and the pull packs the four
  logs, checks the copy and empties them on the server the same day.
- **The live session was never pulled.** A free-for-all session ended only with a map change (33 MB in one folder on a
  quiet morning). The plugin now begins a new folder a minute after the last person has gone.
- **One copy after the wipe.** A session's archive now stays on the server for seven days after it is safe on the PC
  (its folder goes at once), and the pull copies the archive folder to a second disk (`E:\quake-sessions\public`).
- **No index.** `tools/session_index.py` writes `sessions.csv`, a row per session, and answers "who played since".
- **Two folders for every 1v1 join**: the first probe's hook in `plugins/botctl.py` (every person to spectator two
  seconds after joining) is off unless `!autospec on`.
- **Two places on the PC**: `data/public/sessions` was a hand copy of 12 sessions, all of them in the archive.

Run once by hand: the logs of the server (the two kept from the stuck hours among them) arrived as one archive and were
emptied there; 109 sessions indexed; 116 files on the second disk. The plugin changes were started on a private local
server (no error, both Bobbys moving, `minqlx.log` in the data folder); a session's turn-over when the last person
leaves has not been seen with a person yet. They reach the public server with a restart in the night, when it is empty.
